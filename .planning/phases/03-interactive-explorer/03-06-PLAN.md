<objective>
Close two gaps that both live in `src/pages/ExplorerPage.tsx`.

G-03-2b (minor): a well-formed but non-existent survey id shows the heading
"No s'han pogut carregar les enquestes" — HomePage's plural survey-LIST
load-failure wording. Root cause (diagnosed in
`.planning/debug/g-03-2b-wrong-error-copy.md`): the phase-2 error branch at line
176 renders `<ErrorState>` with no `title` prop, so it falls back to
`ErrorState.tsx`'s default title, which is character-identical to HomePage's
heading. `isValidEnquestaId` is a format-only regex, so a non-existent-but-valid
id skips the dedicated not-found branch, reaches phase 2, 404s on `metaUrl(id)`,
and lands in that generic, title-less branch. The plan that specified this
branch only ever specified a message, never a title — this is a design gap
carried faithfully into the implementation, not an implementation slip.

G-03-4b (minor): every chart renders small regardless of available space. Root
cause (diagnosed in `.planning/debug/g-03-4b-graphicwalker-small-canvas.md`,
confirmed against the installed library's own source): GraphicWalker's
`emptyVisualLayout` default is `{ mode: 'auto', width: 320, height: 200 }`, and
in 'auto' mode `dist/renderer/specRenderer.js` sizes its wrapper
shrink-to-content while `dist/vis/react-vega.js` hands Vega-Lite a zero size so
it computes its own small natural footprint. Only `mode: 'full'` measures the
real container via `useResizeDetector()`. The `<GraphicWalker>` mount never
passes the documented `defaultConfig` prop, so every chart is born in 'auto'.

There is a second half to G-03-4b that the debug session's evidence implies but
the gap text does not spell out: GraphicWalker's own root is `w-full h-full`
(`dist/App.js` line 102) feeding a `flex-1 min-h-0` column. A percentage height
resolves against a parent's height, not its min-height, so under today's
min-height-only wrapper that chain collapses. 'full' mode would then measure
nothing and fall through to the same small numbers. Passing `defaultConfig`
without also giving the wrapper a definite height fixes nothing observable.

Purpose: restore EXPL-02's promise of a clear, correct error message and
EXPL-03/EXPL-06's promise of a usable canvas.
Output: `src/pages/ExplorerPage.tsx` with a discriminated data-error state,
distinct not-found and load-failure copy, GraphicWalker configured to fill its
container, and a container that has a height to fill.

Sequencing: this plan runs after 03-05 because Task 2's human check exercises
the full share-link round trip, which cannot pass until 03-05's decode fix has
landed. The two fixes also interact — a chart restored through the `chart` prop
carries its own serialized `layout.size`, so a link copied AFTER Task 2 lands
will carry the fill-the-container mode and restore large. Task 2's human check
verifies that composed behaviour rather than assuming it.
</objective>
