<objective>
Deliver the phase's core value end-to-end in one production-quality tracer slice: a visitor opens `/enquesta/mostra-sintetica`, watches DuckDB-Wasm initialise, watches the committed Parquet load, and lands in a working `<GraphicWalker />` where they can drag `edat`/`satisfaccio`/`segment`/`canal` onto shelves and switch chart types — over real data, with no server.

**As a** person who found a published survey, **I want to** build my own charts from its raw responses in the browser, **so that** I can answer my own questions about the data instead of only seeing the charts someone else chose to publish.

Purpose: this is the highest-risk integration in the project (STATE.md Blockers — GitHub Pages COOP/COEP header limits, Vite worker/wasm asset bundling under a `base` path, Parquet fetch reliability). Proving all of it on one thin path, verified against a real production build rather than only `vite dev`, means an architectural dead-end surfaces after one commit instead of after the header, dictionary, export and share-link work is already layered on top.

Output: `src/services/duckdb.ts`, `src/lib/graphicWalkerFields.ts` (+ unit test), a rewritten `src/pages/ExplorerPage.tsx`, a route-aware full-width `src/App.tsx`, an extended `src/components/ErrorState.tsx`, and `scripts/verify-explorer-assets.mjs`.
</objective>
