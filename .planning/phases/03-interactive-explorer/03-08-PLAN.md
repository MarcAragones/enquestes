<objective>
Close gap G-03-7 (cosmetic): `SurveySummaryModal`'s `<dialog>` opens pinned to the
top-left of the viewport instead of centered.

Root cause, fully diagnosed and CONFIRMED in
`.planning/debug/g-03-7-modal-not-centered.md`: Tailwind v4's Preflight emits a
universal reset — `*, ::before, ::after, ::backdrop { margin: 0 }` — into
`@layer base`. That is an author-origin, normal-priority declaration, and the CSS
cascade resolves origin and importance BEFORE it ever compares specificity. So an
author rule of specificity 0-0-0 unconditionally beats the browser's
user-agent-origin `dialog:modal { position: fixed; inset-block: 0; margin: auto; }`
rule, whose `margin: auto` is the sole mechanism that centers a native `<dialog>`
opened via `showModal()`. Preflight declares no `position` and no `inset`, so those
UA declarations survive: the dialog stays `position: fixed` with its block inset
pinned to 0, but with `margin: 0` it can no longer auto-center in either axis and
collapses to the top-left corner. Confirmed present verbatim in the production
build's compiled CSS (`@layer base{*,:after,:before,::backdrop{...margin:0...}}`),
so this is not a dev-server artifact.

This is a pre-existing defect, not a regression from 03-07 — `git show a4cb543`
confirms the `<dialog>` JSX and its className are byte-identical before and after
that plan, which only touched the lifecycle effect bodies. It was invisible until
now because G-03-5 made the dialog self-dismiss within a fraction of a second, so
nobody could observe its resting position. It matches a known upstream issue,
tailwindlabs/tailwindcss#16372.

The fix is to restore `margin: auto` from the author origin, where it wins the
author-vs-author fight against Preflight: Tailwind declares its layers in the order
`theme, base, components, utilities`, so a utility-layer rule outranks a
base-layer rule regardless of specificity.

Alternative considered and rejected: a global `@layer base { dialog { margin: auto } }`
in `src/index.css`. It would be a same-layer tie against Preflight decided by source
order, making correctness depend on where Vite happens to place the block relative
to the Preflight import — fragile, and invisible from the one component that
actually depends on it. This app has exactly one `<dialog>`; keep the fix at its
point of use where the next reader will find it. Do NOT edit `src/index.css`.

Purpose: restore HOME-03's quick KPI summary to a usable, centered presentation.
Output: a one-line className change in `SurveySummaryModal.tsx`, gated by an
assertion against the built production CSS, plus a human-check that also clears the
two G-03-5 re-test sub-steps left unconfirmed by the last UAT round.
</objective>
