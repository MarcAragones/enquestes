<assumption_delta_decision>
**Signal:** the deterministic assumption-delta scan flagged a pluralization transition in this phase's scope — "choosing among multiple chart types". The identity-model question it raises is not about the mark types themselves (those live entirely inside GraphicWalker's own state and this project never models them); it is about the share payload, where GraphicWalker's restore surface is plural (`chart` takes `IChart[]`) while the product concept is singular ("a link that reproduces the exact current visualization").

**Question:** promote a singular "current chart" into this project's own model and wrap/unwrap it, or carry GraphicWalker's plural container alongside as-is?

**Decision: carry the plural container as-is.** `encodeShareLink` serialises whatever chart collection GraphicWalker hands back, and `decodeShareLink` returns a value shaped for the `chart` prop verbatim. This project introduces no singular "current chart" type of its own.

**Rationale:** the restore side is the confirmed half of the API and it is plural. Inventing a singular wrapper would mean an unwrap on encode and a re-wrap on decode, and every future GraphicWalker version that changes what a chart entry contains would break that translation silently — a link would decode "successfully" into a subtly wrong visualization, which is worse than the D-07 blank fallback. Keeping our model shape-identical to the library's makes the whole translation layer disappear.

**Advisory only** — this checkpoint records the decision; it does not gate the phase.
</assumption_delta_decision>

    `encodeShareLink(spec: unknown): string | null` produces `SHARE_VERSION` + separator + base64url-encoded UTF-8 JSON. Encode via `TextEncoder` to bytes, then to a binary string, then `btoa` — a direct `btoa(JSON.stringify(spec))` throws on any character outside Latin-1, and this survey's dimension values carry accented Catalan text, so that path is a guaranteed runtime failure, not a theoretical one. Convert the base64 to base64url by replacing the plus and slash characters with hyphen and underscore and stripping the padding, so the value survives a URL untouched. Return `null` if serialisation fails; this function must never signal failure by raising.

    `decodeShareLink(raw: string | null, knownFieldNames: string[]): unknown | undefined` runs a fixed sequence, and every single step returns `undefined` on failure rather than throwing. Document at the top of the function, in the style of `formatDate`'s doc comment, that this is a deliberate soft fallback and not the hard trust boundary `parseEnquestaMeta` implements — a stale link is expected staleness as surveys evolve, not attacker input crossing a data boundary, and the visitor should not be shown an error for it (D-07).
    1. Return `undefined` immediately for a null, empty, or non-string input.
    2. Return `undefined` if the input's length exceeds `MAX_SHARE_PARAM_LENGTH`, before any decode work — an oversized crafted payload must not get the chance to consume memory or CPU. This check is first for a reason; keep it first.
    3. Split on the separator, and return `undefined` unless the leading tag equals `SHARE_VERSION`. An unrecognised version is a future format this build cannot read, and a blank explorer is the correct answer.
    4. Reverse the base64url transformation, `atob`, and decode the bytes back through `TextDecoder`. Wrap in try/catch; return `undefined` on any failure.
    5. `JSON.parse` inside the same guard; return `undefined` on failure.
    6. Walk the parsed structure and collect every string that occupies a field-reference position. Return `undefined` if any collected reference is absent from `knownFieldNames`. Use the `chart` prop element type Task 1 recorded to know where field references live; if that structure is deeply nested or version-dependent, a conservative recursive scan for the field-identifier key names Task 1 found is acceptable and preferable to skipping validation. This is the schema-drift control: a link built against an older `meta.json` must not apply a spec referencing a column that no longer exists.
    7. Return the parsed value, shaped exactly as the `chart` prop expects — no wrapping, no normalisation, no singular/plural translation (see the assumption-delta decision above).

    Keep this module pure: no React import, no DOM access, no clipboard access, and no reads of the browser's global location or history objects. URL assembly and clipboard writing belong in Task 3, which keeps this module unit-testable in a node environment with no browser shim. `btoa`/`atob` and `TextEncoder`/`TextDecoder` are all available as globals in modern Node, so the vitest node environment configured in 03-01 needs no change.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| URL to app (`?chart=` query param) | Fully visitor/attacker-controlled payload, decoded client-side and handed to a third-party rendering component |
| App to clipboard | An absolute URL written to the OS clipboard on explicit user action |
| Third-party component boundary (`<GraphicWalker />`) | Decoded spec data crosses into library-owned rendering code |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-10 | Tampering | `decodeShareLink` handling a crafted `?chart=` payload | high | mitigate | Fixed decode sequence where every step returns `undefined` rather than throwing: length cap first, then version-tag match, then guarded base64url/UTF-8 decode, then guarded `JSON.parse`, then every field reference checked against the currently-loaded `meta.json` field names. Unit-tested per input class in Task 2 |
| T-03-11 | Tampering | Schema drift — a spec referencing a column removed from a re-published survey | medium | mitigate | Step 6 of the decode validates every collected field reference against `knownFieldNames` derived from the freshly-loaded meta; any unmatched reference discards the whole spec (Task 2, D-07) |
