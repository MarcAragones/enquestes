<objective>
Close UAT gap G-05-4: a share link copied from a real wide survey is ~57 KB long and the browser/server rejects it with HTTP 431 before any app code runs.

Root cause (already diagnosed, see `05-UAT.md`): `encodeShareLink` has no output-length cap, and GraphicWalker's `VizSpecStore.exportCode()` embeds the survey's ENTIRE field catalogue in `encodings.dimensions`/`encodings.measures` — so payload size scales with the survey's field count (283/291/263 fields for the three published surveys), not with chart complexity.

Fix, ENCODE side only: strip the field catalogue before serialising, enforce the existing `MAX_SHARE_PARAM_LENGTH` cap on what the encoder emits, rebuild the catalogue from the currently-loaded survey's own fields when a link is restored, and fail the copy-link action with a visible message when a chart genuinely cannot fit.

Purpose: restore ROADMAP Phase 5 Success Criterion 4 ("a `?chart=` link copied from one real survey restores that exact chart when reopened") for the real surveys that shipped in Phase 4 — the criterion currently fails on every one of them, because all three are wide.

Output: a share link that opens, restores the same chart, leaves the field panel usable, and refuses loudly instead of silently when it cannot.

Non-goals, explicitly out of scope for this plan:
- `decodeShareLink`'s validation logic (steps 1-7) is NOT touched. Its length cap, version tag, UTF-8-fatal decode, shape guard and shelf-fid allow-list were threat-modelled in Phase 3 (T-03-10/11/12, CR-01) and are covered by 19+ tests. This plan only adds a rehydration step that runs AFTER decode returns, in a separate module.
- No new npm dependency. No pipeline/Python change. No `public/data/` change.
- Charts whose shelves reference a GraphicWalker-computed field (a user-created bin or SQL field, `computed: true`, e.g. `bin_edat_...`) already do not survive a share link today: its fid is neither in `meta.json` nor a GraphicWalker virtual fid, so step 7 of `decodeShareLink` discards the whole payload. That is a pre-existing limitation, unchanged here — do not chase it.
</objective>
