<objective>
Publish the privacy-approved surveys to `public/data/`, then prove mechanically that the published set is internally consistent and that the index upsert lost nothing and duplicated nothing.

Purpose: ROADMAP success criterion 3 requires that every approved survey has a correct index entry with no entry lost or duplicated by the upsert. Nothing in the repository can check that today — `npm run verify:pages` proves the index is served as an array, not that its contents match the files beside it. This plan closes that gap with a check that also serves Phase 5, where the same invariants must hold after `mostra-sintetica` is removed.

Output: the approved artifacts under `public/data/`, a new `scripts/verify_publicacio.py` that fails loudly on a duplicate id, a count mismatch, or an orphan file, fail-first coverage for that verifier, and a green run of the full build and preview gate against the published data.

Scope boundary: `mostra-sintetica` stays. Retiring it is Phase 5, and this plan asserts its entry is still present and unchanged.
</objective>

  <action>
Create `scripts/verify_publicacio.py` as a standalone PEP 723 script, invoked as `uv run scripts/verify_publicacio.py`, with `requires-python >= 3.11` and `pandas`, `pyarrow` as dependencies, matching the header on `scripts/convert_enquesta.py`. Give it a `main(argv=None) -> int` and a `if __name__ == "__main__": raise SystemExit(main())` tail, matching the existing scripts.

Arguments:
- `--data-dir`, default `public/data`, the directory holding `enquestes_index.json` and the `enquestes/` subdirectory.
- `--expect-ids`, optional comma-separated list. When given, the index must contain exactly these ids, no more and no fewer; a missing id and an unexpected id are both failures and both are named in the output.

Checks, all run to completion so a single invocation reports every problem rather than stopping at the first:

1. `enquestes_index.json` exists, parses as JSON, and passes `schema.validate_index`.
2. No `id` appears more than once in the index. This is the upsert-integrity check ROADMAP success criterion 3 turns on: a duplicated entry is what a broken upsert produces.
3. Every index entry's `id` satisfies `schema.is_valid_enquesta_id`.
4. For every index entry, both `enquestes/<id>_respostes.parquet` and `enquestes/<id>_meta.json` exist and are non-empty.
5. Every `<id>_meta.json` parses and passes `schema.validate_meta`, and its `id`, `title`, `date`, `description` and `n` are equal to the index entry's corresponding values. A meta that disagrees with its index entry means a visitor's card and a visitor's explorer disagree about the same survey.
6. Every meta's `n` equals its own Parquet file's row count, read via `pyarrow.parquet.ParquetFile(path).metadata.num_rows`.
7. Every meta's `fields` name set equals its own Parquet schema's column name set, read via `pyarrow.parquet.read_schema(path).names`. This is the per-survey generalisation of the converter's step-12 read-back.
8. No orphans: every file under `enquestes/` matching `<something>_respostes.parquet` or `<something>_meta.json` resolves to an id that has an index entry. An artifact with no entry is invisible to the site but permanently public.

Output and exit codes:
- Always print a report, in the register `privacy.format_checklist_report` established: a header, the effective `--data-dir`, one line per survey stating its id, row count and column count, and either an explicit statement that every check passed with the number of surveys checked, or one line per failure naming the survey and the specific check.
- Never print a bare pass without stating how many surveys were checked — a clean report over zero surveys is a failure to check, not a pass.
- Report ids, filenames, counts and column names only. Never read or print a cell value from any Parquet file; `num_rows` and the schema come from Parquet metadata and need no row read.
- Exit 0 when every check passes, 1 when any check fails or the index is missing or unreadable.

Then add `VerifyPublicacioTests` to `scripts/pipeline_selftest.py`, proving the verifier has teeth before it is trusted against real data. Each test builds a synthetic published set inside a `TemporaryDirectory()` — a small `pandas` DataFrame written with `to_parquet`, a matching meta dict written with `schema.write_json`, and an index array — and calls `verify_publicacio.main([...])` with `--data-dir` pointed at it. Cover: a fully consistent set returns 0; an index with the same id twice returns 1; a meta whose `n` disagrees with its Parquet row count returns 1; a meta whose `fields` name set disagrees with its Parquet schema returns 1; an index entry whose Parquet file is missing returns 1; an orphan Parquet with no index entry returns 1; a set where `--expect-ids` names an id the index does not contain returns 1. Import `verify_publicacio` alongside the existing imports.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| approved artifacts → `public/data/` → public git history → GitHub Pages | The permanence boundary. This plan is the moment real respondent data crosses it. |
| `enquestes_index.json` → the React app → every visitor | The index is the only thing the homepage reads to decide which surveys exist. A wrong or duplicated entry is a wrong site. |
| existing index entries → `compute_upserted_index` → rewritten index | Each publication run rewrites the whole array. A sibling entry lost or duplicated here is silently wrong until someone notices. |

Explicitly out of scope, stated so the narrowness is deliberate: no authentication, no identity and therefore no Spoofing surface; no database and therefore no injection surface; no server-side request handling and therefore no denial-of-service surface. The site is static files served by GitHub Pages.

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-10 | Information Disclosure | publishing a survey whose privacy findings were never resolved | high | mitigate | Task 1's precondition requires 04-02's summary to carry an explicit resolution for every finding of every survey, and its action halts rather than running a survey with an unresolved finding. `--confirm-privacy-review` is passed only on the strength of that record. |
| T-04-11 | Information Disclosure | publishing a column set different from the one the operator reviewed | high | mitigate | Task 1 compares each publication run's free-text and cardinality drop lists against what 04-02 recorded for that survey and halts on any difference, so a changed input or flag invalidates the review instead of shipping past it. |
| T-04-12 | Tampering | the index upsert losing or duplicating a sibling entry | medium | mitigate | `compute_upserted_index` replaces in place or appends and never rebuilds; `scripts/verify_publicacio.py` then independently proves no id repeats and no entry is orphaned, and that check is itself proven fail-first by `VerifyPublicacioTests`. The `mostra-sintetica` entry is compared byte for byte against a pre-run baseline. |
| T-04-13 | Information Disclosure | the publication verifier's report leaking respondent data | low | mitigate | The verifier reads Parquet metadata only — `num_rows` and the schema names — never row content, and reports ids, filenames, counts and column names. An acceptance criterion asserts no cell value appears in its output. |
| T-04-14 | Tampering | hand-edited index or meta bypassing the validate-before-write gates | medium | mitigate | Task 1 forbids hand-editing `enquestes_index.json` and any `_meta.json`; every change comes from a converter run, so `schema.validate_meta`, `schema.validate_index` and the step-12 Parquet read-back always apply. Task 2's verifier catches a hand-edit after the fact. |
| T-04-15 | Elevation of Privilege | `--data-dir` path composition in the new verifier | low | accept | The verifier only reads; it composes no write path, and a wrong `--data-dir` produces an exit-1 report rather than a write outside the tree. |
| T-04-SC | Tampering | package-manager installs | n/a | accept | No package is installed in this plan. `scripts/verify_publicacio.py` declares only `pandas` and `pyarrow` in its PEP 723 header — both already declared by `scripts/convert_enquesta.py` and already in use in this repository — so no new package enters the project and the package legitimacy gate is not triggered. |

Canon-referral breadcrumbs (surfaced, deliberately not minted as prohibitions): output-path traversal is canon and is covered by `/gsd-secure-phase` plus the existing `_resolve_output_paths` guard; GDPR retention and consent for published respondent data is canon and is covered by `/gsd-secure-phase`.
