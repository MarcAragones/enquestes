## Interface contracts defined by this plan

This is the Phase 2 hand-off surface for per-survey metadata. Phase 2's conversion script emits
files that must satisfy it; Phase 3 reads `fields` from the same file for the data dictionary.

**On-disk layout under `public/data/`** (locked here, do not renegotiate downstream):

- `enquestes_index.json` — the catalog array, locked in plan 01-01.
- `enquestes/<id>_meta.json` — one per survey.
- `enquestes/<id>_respostes.parquet` — one per survey (Phase 2 produces, Phase 3 consumes).

**New exports on `src/lib/enquestes.ts`:**

- `MIN_KPI_SAMPLE` — `10`. The sample size below which a KPI value is withheld.
- `isValidEnquestaId(id: string): boolean` — true only for `/^[A-Za-z0-9._-]{1,64}$/`.
- `metaUrl(id: string): string` — `dataUrl('enquestes/' + encodeURIComponent(id) + '_meta.json')`.
- `parseEnquestaMeta(input: unknown): EnquestaMeta` — trust-boundary validator, throws `Error('Format inesperat')`.

**New component:**

- `SurveySummaryModal` — props `{ enquestaId: string; onClose: () => void }`.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Visitor-controlled `:id` route param / `?enquesta=` search param → fetch path | The survey id is fully attacker-controllable and is composed into a request URL. |
| GitHub Pages CDN → browser (`enquestes/<id>_meta.json`) | A second untrusted-shaped JSON input, rendered as headline numbers a reader will trust. |
| Published aggregate KPI → any reader | A statistic over a small subgroup can identify an individual even though no identifying field is published. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-08 | Tampering (path manipulation via untrusted input) | `metaUrl` in `src/lib/enquestes.ts`, consumed by `SurveySummaryModal` and `ExplorerPage` | high | mitigate | Two independent controls: `isValidEnquestaId` restricts the id to `/^[A-Za-z0-9._-]{1,64}$/` before any request is built, and `metaUrl` percent-encodes it so no path separator can survive even if validation were bypassed. `HomePage` and `ExplorerPage` both gate on the validator, asserted by grep in Task 2's verify block. |
| T-01-01 | Tampering / Denial of Service | `parseEnquestaMeta` in `src/lib/enquestes.ts` | medium | mitigate | Full shape validation of the meta document — object-ness, every required scalar type, the `kpis` array element shape, and the `fields` `type` enum — before anything reaches the render tree, throwing into the modal's failure state rather than crashing (ASVS V5). |
| T-01-02 | Tampering (content injection) | `src/components/SurveySummaryModal.tsx` | high | mitigate | `title`, `description`, KPI `label` and `unit` all render as plain JSX text nodes, which React HTML-escapes. React's raw-HTML injection prop stays banned across `src/`, asserted by a negative source grep in both tasks' verify blocks. |
| T-01-09 | Information Disclosure (re-identification) | KPI rendering in `src/components/SurveySummaryModal.tsx` | medium | mitigate | Values computed over fewer than `MIN_KPI_SAMPLE` (10) effective respondents are withheld and the withholding is stated, and every displayed value carries its sample size so a reader can judge it. This is a client-side presentation control on data an author already chose to publish; the authoritative control is Phase 2's DATA-03 privacy checklist at conversion time, which is where a quasi-identifier is caught before it is ever committed. |
| T-01-05 | Information Disclosure | `src/components/SurveySummaryModal.tsx` failure arm | low | accept | The failure body is a fixed Catalan string; the caught error, its message, and the attempted URL are never interpolated into visible text. Residual console visibility is accepted — the site is fully public with no secrets, no session and no privileged endpoint. |
| T-01-SC | Tampering (supply chain) | none | n/a | transfer | This plan installs no packages. Supply-chain risk for the phase is carried by plans 01-01 and 01-02, where the legitimacy audit and the blocking-human icon-package checkpoint live. |
</threat_model>
