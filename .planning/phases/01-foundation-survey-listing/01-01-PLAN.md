## Interface contracts defined by this plan

Later tasks in this phase (and Phase 2's Python pipeline, and Phase 3's explorer) build against
these. They are defined in Task 3 and must not drift.

`src/types/enquesta.ts`:

- `EnquestaIndexEntry` — `{ id: string; title: string; date: string; description: string; n: number }`.
  One element of the `enquestes_index.json` array. `date` is an ISO `YYYY-MM-DD` string; `n` is
  the participant count.
- `EnquestaMetaKpi` — `{ label: string; value: number | string; unit?: string; n?: number }`.
  One headline KPI in `[id]_meta.json`. `n` is the per-KPI sample size when it differs from the
  survey-level `n`.
- `EnquestaMetaField` — `{ name: string; label?: string; description?: string; type: 'dimension' | 'measure' }`.
  Part of the meta contract Phase 2 emits and Phase 3 consumes for the data dictionary and field
  typing; Phase 1 types it and does not render it.
- `EnquestaMeta` — `{ id: string; title: string; date: string; description: string; n: number; kpis: EnquestaMetaKpi[]; fields?: EnquestaMetaField[] }`.
- `FetchState<T>` — discriminated union `{ status: 'loading' } | { status: 'error'; message: string } | { status: 'success'; data: T }`.

`src/lib/enquestes.ts`:

- `dataUrl(relativePath: string): string` — returns `import.meta.env.BASE_URL` concatenated with
  `data/` and `relativePath`. The ONLY place in the codebase that composes a data URL.
- `parseEnquestesIndex(input: unknown): EnquestaIndexEntry[]` — validates at the fetch trust
  boundary and throws `Error('Format inesperat')` on any shape violation.

  <decision>Confirm the client-routing strategy for deep links on GitHub Pages</decision>
  <context>
    CONTEXT.md delegated this to Claude's discretion; RESEARCH.md resolved it in favour of
    `BrowserRouter` + the `404.html` redirect pair. It is surfaced here rather than assumed
    because the choice fixes the project's PUBLIC URL SHAPE, which is a one-way door: once real
    survey links are shared, bookmarked, or indexed, switching schemes breaks every one of them
    and GitHub Pages cannot issue a server-side redirect to rescue them. Phase 3's shareable
    chart-state links (EXPL-11, query-param encoded) also sit directly on top of this choice.
    Option A is the researched recommendation and is what an unattended run will take.
  </context>
  <options>
    <option id="browser-router">
      <name>BrowserRouter + 404.html redirect pair (recommended)</name>
      <pros>Clean, shareable URLs (`/enquestes/enquesta/abc123`). Query params stay ordinary query params, which is what EXPL-11's shareable chart links want. Matches GitHub's native Actions/Pages deploy flow and the well-tested `rafgraph/spa-github-pages` algorithm.</pros>
      <cons>Requires the `404.html`/`index.html` script pair to be exactly right; a wrong `pathSegmentsToKeep` breaks deep links in a way that only shows up on the deployed site, not in dev.</cons>
    </option>
    <option id="hash-router">
      <name>HashRouter</name>
      <pros>Cannot 404 on refresh — the hash never reaches the server, so zero GitHub Pages configuration and no redirect scripts at all.</pros>
      <cons>URLs become `/enquestes/#/enquesta/abc123`. Query params must live inside the hash, which complicates EXPL-11's shareable chart-state links. Switching away later breaks every shared link.</cons>
    </option>
  </options>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| GitHub Pages CDN → browser (`public/data/*.json`) | Untrusted-shaped input crosses here: the app has no control over what the static JSON actually contains at fetch time, and it is parsed into the render tree. |
| Visitor-controlled URL → `404.html` encoder → `index.html` restore script | Attacker-controllable path and query text is read, re-encoded, and written back into browser history before React boots. |
| GitHub Actions runner → GitHub Pages publish | The only privileged step in the system; it holds an OIDC token and publish rights. |
| npm registry → local/CI `node_modules` | Third-party code enters the build and ships to every visitor. |
