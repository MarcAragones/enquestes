# Phase 3 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

## Design System

| Property | Value |
|----------|-------|
| Tool | none — no `components.json` detected; the project already uses a hand-rolled Tailwind v4 token system (`src/index.css` `@theme` block: zinc neutral ramp + a single `--color-accent*` hue) across 2 completed phases. Introducing shadcn now would fragment an already-consistent, working system rather than help it — not asked as a gate question this phase; see rationale below. |
| Preset | not applicable |
| Component library | none — plain Tailwind classes + native HTML elements (`<dialog>`, `<button>`). The one third-party UI surface this phase adds, `<GraphicWalker />`, ships its own internal chrome via its `styled-components` peer dependency and is explicitly NOT to be re-styled or reached into (CONTEXT.md D-06) — none of this contract's tokens apply inside its canvas. |
| Icon library | `lucide-react` (already installed and in use: `AlertTriangle`, `Inbox`, `Moon`, `Sun`) — new icons this phase: `Copy` (Copy-link button, see Copywriting Contract) |
| Font | `--font-sans` = `ui-sans-serif, system-ui, -apple-system, "Segoe UI", Roboto, "Helvetica Neue", Arial, sans-serif` (`src/index.css`) |

**shadcn gate rationale:** Phase 1 and Phase 2 already shipped a complete, consistent hand-rolled design system (see `SurveyCard.tsx`, `ErrorState.tsx`, `EmptyState.tsx`, `SurveySummaryModal.tsx` — all plain Tailwind on the `zinc`/`accent` tokens). This phase adds one small new component surface (`ExplorerHeader`, a data-dictionary panel, loading/error states) that must visually match those existing components, not a new library. GraphicWalker's own UI is unaffected by shadcn either way (it brings its own `styled-components`-based chrome). Initializing shadcn here would add a second, unused styling system to the repo for zero benefit — skipped by design judgment rather than asked as a live gate question.

## Visual Hierarchy

The GraphicWalker canvas is the primary focal point of the explorer page; the `ExplorerHeader` (back-link, survey title, dark-mode toggle, Copy-link button) is secondary chrome. The header stays compact (single row, `py-4`) so the canvas claims the dominant share of vertical viewport space; the data-dictionary panel is a collapsed-by-default, opt-in secondary surface that never competes with the canvas for default visual weight.

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gaps |
| sm | 8px | Compact inline spacing (e.g. `mt-2` on retry buttons) |
| md | 16px | Default element spacing (`gap-4`, `space-y-4`, header `py-4`) |
| lg | 24px | Section/header padding (`px-6`, `mt-6` button rows) |
| xl | 32px | Layout gaps (page-level `py-8`) |
| 2xl | 48px | Major section breaks (reserved, not yet used) |
| 3xl | 64px | Page-level spacing (reserved, not yet used) |

Exceptions:
- **12px** (`gap-3`, `p-3`, `space-y-3`) — exists elsewhere in the codebase as legacy precedent (KPI card padding, dialog button gaps in `SurveySummaryModal.tsx`, both shipped in earlier phases). **Not part of the standard scale and not reused in Phase 3.** The data-dictionary panel's internal spacing (between field-name rows, icon-to-description gaps) uses **8px** (`gap-2`, `space-y-2`) instead, staying on the declared 4/8/16/24/32/48/64 scale; the panel's own outer padding is 16px (`p-4`, see below).
- **20px** (`p-5`) — established `SurveyCard.tsx` card padding. Not reused this phase (Phase 3 introduces no new outer "card" surface at that scale — the data-dictionary panel is a secondary/nested surface, use 16px `p-4` for it instead, per Typography/Color sections below).
- **Layout width, not padding:** `App.tsx`'s shared `<main>` wraps all routes in `mx-auto max-w-3xl px-6 py-8` (768px cap, sized for the card-grid homepage). `ExplorerPage.tsx` must render **outside** this width cap — `<GraphicWalker />` needs the full viewport width to function as a usable drag-and-drop canvas; a 768px-capped explorer would be unusable, not just cramped. Implement as a route-level full-width wrapper (e.g. the explorer route renders its own top-level container instead of relying on `App.tsx`'s shared `<main>`), keeping `px-6`/`py-8` outer breathing room but dropping `max-w-3xl` specifically for this route.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Label | 12px (`text-xs`) | 400 | 1.4 — dates, KPI sub-labels, field-name captions; uppercase + `tracking-wide` only for date-style category labels (existing pattern, do not apply uppercase to field names) |
| Body | 14px (`text-sm`) | 400 | 1.5 — descriptions, field descriptions, button labels, secondary copy |
| Heading | 16px (`text-base`) | 600 | 1.3 — card/section titles, KPI values, data-dictionary panel field names |
| Display | 18px (`text-lg`) | 600 | 1.2 — page-level title only (`ExplorerHeader`'s `<h1>`, matching `App.tsx`'s existing `<h1>` and `SurveySummaryModal`'s `<h2>`) |

**Two weights only: 400 (regular) and 600 (semibold).** Note: `ErrorState.tsx`'s existing retry button uses `font-medium` (500) — a pre-existing minor deviation from this rule. Do not propagate it: all new Phase 3 buttons (Copy-link, any new retry button) use `font-semibold` (600), matching `SurveySummaryModal`'s and `SurveyCard`'s button/heading weight, not `font-medium`.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `zinc-50` (light) / `zinc-950` (dark) | Page background (`App.tsx` body) |
| Secondary (30%) | `white` (light) / `zinc-900` (dark), borders `zinc-200`/`zinc-800` | Cards, modal, data-dictionary panel surface, `ExplorerHeader` border |
| Accent (10%) | `--color-accent` `#2563eb`, hover `--color-accent-strong` `#1d4ed8`, dark-hover `--color-accent-soft` `#60a5fa` | Reserved for: primary CTA button fills (Copy-link, retry button), the back-link text color, hover border on interactive cards/buttons, `focus-visible` outline ring. **Not** used for: body text, static icons, backgrounds outside interactive elements. |
| Destructive | `red-600`/`red-400` (dark), border `red-300`/`red-900`, bg `red-50`/`red-950/40` | Error-state alert boxes only (DuckDB engine-init failure, Parquet load/query failure — see Copywriting Contract). **No destructive actions exist in Phase 3 scope** (no delete/remove UI) — this token is purely for error states, never a confirm-destructive-action button. |

Accent reserved for: Copy-link button fill, retry button fill, back-link text, hover border on `ExplorerHeader` buttons, `focus-visible` rings — never for body/label text, panel borders at rest, or icons outside an active/hover interactive state.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | **"Copia l'enllaç"** — Copy-link button (D-05/D-06), `Copy` icon from `lucide-react`, lives in `ExplorerHeader` next to the back-link and dark-mode toggle |
| Copy-link confirmation | On click, the button label swaps to **"Copiat!"** for 2 seconds then reverts — avoids building a separate toast/snackbar component for a single transient confirmation |
| Loading state 1 (engine init) | **"Inicialitzant el motor de consultes…"** — shown while DuckDB-Wasm's bundle selects, Worker spins up, and `instantiate()` runs (EXPL-01, phase 1 of 2) |
| Loading state 2 (data load) | **"Carregant les dades de l'enquesta…"** — shown while the Parquet fetches and the initial query runs (EXPL-01, phase 2 of 2) |
| Error state 1 (engine init failure) | **"No s'ha pogut inicialitzar el motor de consultes."** + **"Prova-ho amb un altre navegador; aquesta aplicació necessita compatibilitat amb WebAssembly."** — no retry button (a different browser/environment is needed, not a retry; per RESEARCH.md's EXPL-01/02 recommendation) |
| Error state 2 (data load/query failure) | **"No s'han pogut carregar les dades de l'enquesta."** + retry button **"Torna-ho a provar"** — reuses `ErrorState.tsx`'s exact visual pattern (red alert box, `AlertTriangle` icon, retry button) verbatim for consistency, since this failure is plausibly transient (network blip) |
| Data dictionary — empty | **"Aquesta enquesta no té camps documentats."** — shown when `meta.json`'s `fields` array is absent or empty (EXPL-09 edge case) |
| Data dictionary — panel heading | **"Diccionari de dades"** with a field count, e.g. **"Diccionari de dades (6)"** — collapsed by default per RESEARCH.md's recommendation |
| Back-link | **"← Torna al llistat d'enquestes"** — reused verbatim from the existing `ExplorerPage.tsx` stub, plain text arrow prefix (not a lucide icon), consistent with the current codebase's pattern |
| Shareable-link malformed/stale param (D-07) | *(no copy)* — silent fallback to the default/blank explorer state, explicitly no error message shown per locked decision D-07; do not invent copy for this case |
| Destructive confirmation | Not applicable — no destructive actions exist in Phase 3 scope |

| Category | Element(s) | Status | Resolution / Reason |
|----------|------------|--------|---------------------|
| empty | Data dictionary panel (EXPL-09, list-collection) | ✅ covered | `meta.json`'s `fields` is optional/may be empty — panel renders the "Data dictionary — empty" copy above instead of a blank collapsed toggle with nothing inside |
| empty | GraphicWalker `dataSource` on a zero-row Parquet (interactive-control/list-collection) | 🧪 backstop | No project-authored copy for a zero-row dataset — GraphicWalker's own empty-canvas rendering is assumed sufficient; needs a held-out check against an actual zero-row Parquet before this can be marked fully covered |
| loading | DuckDB-Wasm init + Parquet fetch/query (EXPL-01, interactive-control) | ✅ covered | Two distinct phases, each with its own visible copy (see Copywriting Contract "Loading state 1/2") — resolves the ambiguity of a single combined spinner across two genuinely different failure points |
| error | DuckDB engine init failure vs. Parquet load/query failure (EXPL-02, interactive-control) | ✅ covered | Two distinct error messages; only the data-load failure gets a "Torna-ho a provar" retry button (engine-init failure is not retry-recoverable — see Copywriting Contract "Error state 1/2") |
| error | Malformed/stale `?chart=` shareable-link param (EXPL-11, D-07, interactive-control) | ✅ covered | Locked decision: silent fallback to the default/blank explorer state, explicitly no error copy shown — resolved as "no error UI," not left ambiguous |
| populated | GraphicWalker canvas with real survey data (EXPL-03/04, interactive-control/list-collection) | ✅ covered | Develop and manually verify against the committed `mostra-sintetica_respostes.parquet` (250 rows, 6 fields: 3 measures + 3 dimensions) per CONTEXT.md code_context — the one real dataset available this phase |
| partial | Data dictionary entries missing `label`/`description` (EXPL-09, list-collection) | ✅ covered | Falls back to the raw field `name` when `label` is absent (matches `graphicWalkerFields.ts`'s existing `name: f.label ?? f.name` pattern) and omits the description line entirely rather than rendering "undefined" or a placeholder dash |
| overflow | Long survey title in `ExplorerHeader` (D-03, nav) | ✅ covered | `truncate` + native `title` attribute tooltip on the `<h1>` — extends (does not contradict) D-03's "wrap/truncate naturally," and specifically prevents the back-link/dark-toggle/copy-link cluster from being pushed off-screen on a narrow header row |
| overflow | Long field descriptions inside the data-dictionary panel (static-content) | ✅ covered | Panel scrolls internally (`max-h-*` + `overflow-y-auto`) rather than growing unbounded and pushing the GraphicWalker canvas further down the page |
| overflow | `ExplorerPage` content width vs. `App.tsx`'s shared `max-w-3xl` (static-content) | ✅ covered | GraphicWalker needs full viewport width to function as a usable canvas — `ExplorerPage.tsx` must render outside the shared 768px-capped `<main>`; see Spacing Scale exceptions |
| zero-one-many | Data dictionary field count: 1 field vs. many (list-collection) | ✅ covered | Simple stacked list, no pluralization-sensitive copy needed — the only place a count appears is the panel heading ("Diccionari de dades (N)"), which reads correctly at any N |
| long-text | Field descriptions/labels inside GraphicWalker's own internal drag-source panel (interactive-control) | ⚠ unresolved | GraphicWalker's internal field-list truncation behavior is not controlled by this project's CSS (D-06 explicitly keeps custom styling out of its chrome) — planner should treat any visual clipping there as GraphicWalker's own responsibility, not something Phase 3 code can fix; surfaced as an assumption, not silently dropped |
| loading/overflow | GraphicWalker canvas responsiveness at small/medium screens (EXPL-06, interactive-control) | 🧪 backstop | D-03 explicitly declines special responsive handling beyond Tailwind flex-wrap on the header; GraphicWalker's own layout behavior at narrow viewports is untested by this project — needs a manual visual check against a real production build at execute/verify time (per STATE.md Blockers: "verify against a real production build, not just dev"), not assumed safe |
